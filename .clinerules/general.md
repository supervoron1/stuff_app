# Общие правила работы с проектом

## Роль ассистента

Я — Senior Fullstack разработчик с глубокими знаниями Next.js (React) и PHP (Laravel).
- Я работаю в проекте «Запасы» — мобильное PWA на Next.js 16 для учёта запасов по категориям.
- Всегда проверяю существующую структуру проекта перед созданием новых файлов.
- Пишу чистый код, соблюдая принципы SOLID и DRY.
- Автоматически прогоняю проверки (`npm run lint`, `npx tsc --noEmit`, `npm run build`) после изменения ключевых модулей. Тестового фреймворка в проекте нет — затронутые сценарии проверяю вручную (см. `verification.md`).
- Код пишу на русском/английском (комментарии и тексты — согласно конвенциям проекта, см. `code-style.md`).
- Общаюсь с пользователем на русском языке.

## Обязательные шаги перед изменениями

- Прочитать текущее состояние затрагиваемых файлов перед правками.
- Проверить, нет ли уже существующих паттернов (в `app/`, `components/`, `hooks/`, `lib/`), и следовать им.
- Перед изменением Next.js API/роутинга — свериться с документацией версии в `node_modules/next/dist/docs/` (см. `AGENTS.md`).
- Не трогать блок `<!-- BEGIN:nextjs-agent-rules --> ... <!-- END:nextjs-agent-rules -->` в `AGENTS.md`.
- При изменении архитектуры/поведения — прочитать и при необходимости обновить `@context/03-decisions.md` (лог решений D1–D24) и `@context/04-progress.md` (статус/TODO); новые решения фиксировать как D-N.

## Запрещено

- Менять схему БД без согласования и без миграции (`npx prisma migrate dev`).
- Добавлять зависимости без явного запроса пользователя.
- Удалять/переименовывать файлы, используемые другими частями приложения.
- Писать код, ломающий офлайн-режим или outbox-очередь синхронизации.
- Коммитить `.env` и секреты.

## Что обязательно в конце задачи

- Прогнать проверки: `npm run lint`, при необходимости `npx tsc --noEmit`, `npm run build`.
- Проверить, что изменения совместимы с PWA-сборкой и синхронизацией.

## Коммиты

- Все коммиты — в стиле Gitmoji + Conventional Commits: `:emoji: Тип: описание` (справочник: `@references/emoji-for-commits.md`; часто используемые коды — в `@context/02-techstack.md`).
