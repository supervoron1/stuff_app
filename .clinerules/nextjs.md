# Правила по Next.js (версия 16)

> ⚠️ Проект на **Next.js 16.3.0** — API и конвенции могут отличаться от того, что известно по старым версиям. Перед написанием кода с Next.js API — читать документацию установленной версии в `node_modules/next/dist/docs/`.

## App Router

- Маршрутизация — только App Router (папка `app/`), без `pages/`.
- Роуты API — файлы `route.ts` в `app/api/*` (например `app/api/sync/route.ts`).
- `layout.tsx`, `page.tsx`, `manifest.ts` — по существующим конвенциям проекта.

## Компоненты

- По умолчанию компоненты — Server Components; `"use client"` добавлять только при использовании хуков, событий или браузерных API.
- Офлайн-логику (кэш Dexie, синхронизацию) держать в `lib/db.ts` и `lib/sync.ts`; React-обвязку — в хуках (`hooks/use-inventory.ts`); UI — в клиентских компонентах `components/`.

## Данные

- Чтение данных на сервере — через `lib/data.ts`.
- **Основной путь мутаций — outbox → `POST /api/sync`** (offline-first: изменения копятся в Dexie-очереди и отправляются при появлении сети; сервер возвращает снимок в том же ответе). Server Actions в `lib/actions.ts` — вспомогательный механизм (формы и т.п.).
- Прямые запросы Prisma в компоненты не класть — только через слой `lib/`.
- Не передавать в клиентские компоненты несериализуемые значения (функции, классы, экземпляры Prisma).

## PWA / публичные файлы

- Service Worker, иконки и манифест — не ломать; изменения в `public/` согласовывать.
- `app/manifest.ts` — единственный источник манифеста.
- **Релиз PWA**: изменился любой кэшируемый файл (включая сам `sw.js`) → поднять `CACHE_NAME` в `public/sw.js` (сейчас `inventory-v2.2.3`). `?v=` у иконок в `app/manifest.ts` / `apple-touch-icon` менять только при смене самих иконок (чек-лист и генерация favicon — в `@context/02-techstack.md`, раздел «Релиз»).
