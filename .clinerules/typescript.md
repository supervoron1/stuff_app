# Правила TypeScript

## Общие требования

- Проект на `strict: true` (см. `tsconfig.json`) — типизировать всё явно.
- Общие доменные типы выносить в `lib/types.ts`.
- Типы, используемые и на клиенте, и на сервере — без серверных зависимостей (иначе будет ошибка сборки клиента).
- Значения из БД (Prisma-типы) приводить к доменным типам при передаче на клиент.
- `zod` — обязателен для валидации входных данных в новых Server Actions и новых API-эндпоинтах; схемы размещать рядом с точками входа (пример — `categorySchema`/`productSchema` в `lib/actions.ts`). Существующие `app/api/sync/route.ts` и `app/api/upload/route.ts` пока валидируют вручную — при их доработке приводить к zod.
- Статусы, цвета, интервалы — только из `lib/constants.ts`, без магических строк.

## Чего избегать

- `any` — запрещён (допустим только с явным комментарием-обоснованием, лучше `unknown`).
- Избыточных типов-обёрток там, где хватает существующих доменных типов.
- Несоответствия типов между `lib/types.ts`, Prisma-схемой и сущностями Dexie.
