# Процесс работы и проверка

> Заготовка. Определи обязательный минимум проверок перед сдачей работы.

## Минимальный процесс

1. **Понять задачу** — изучить затронутые файлы и связанные слои (UI ↔ hooks ↔ lib ↔ БД).
2. **Спланировать** — кратко описать план изменений и затронутые файлы.
3. **Внести изменения** — небольшими проверяемыми шагами.
4. **Проверить**:
   - `npm run lint` — без новых ошибок ESLint;
   - `npx tsc --noEmit` (или `npx tsc`) — без ошибок типов;
   - `npm run build` — сборка проходит (особенно важно после изменений роутов/Server Actions/PWA);
   - затронутые сценарии: CRUD, смена статуса, drag-n-drop, офлайн-очередь, синхронизация;
   - офлайн-режим: изменения при отсутствии сети копятся в outbox (Dexie) и отправляются при появлении сети — не ломать `lib/db.ts` / `lib/sync.ts`;
   - тестов в проекте нет — затронутые сценарии проверяются вручную.
5. **Отчитаться** — что изменил, как проверил, какие риски остались.

## Правила безопасности

- Никогда не выводить в коде/логах секреты из `.env`.
- Не менять `.gitignore` так, чтобы `.env` попал в репозиторий.
- Не применять миграции к продакшену без явного согласования.
